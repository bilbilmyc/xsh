# XSH Desktop

这是 XSH 的 Tauri 2 桌面壳和 React/TypeScript 前端。

## 开发

从仓库根目录执行：

```bash
pnpm install --frozen-lockfile
pnpm --filter desktop run dev
```

前端只构建不启动 Tauri：

```bash
pnpm --filter desktop run build
```

后端位于 `src-tauri`，跨 crate 的 SSH、SFTP、存储和安全能力位于仓库根目录的 `crates/` 中。

## macOS 应用图标

macOS 图标在 1024×1024 画布中使用居中的 824×824 图案，四周保留透明留白，使启动台和 Dock 中的视觉尺寸与其他应用一致。

修改 `src/assets/xsh-icon.svg` 后，从仓库根目录执行：

```bash
pnpm run icons:macos
```

此命令从共享 SVG 生成带留白的 `src-tauri/icons/icon.icns`。生成后的文件应一起提交，供本地和 CI 打包使用。

## 终端内命令建议

终端工具栏中的「命令建议」会在当前提示符附近打开建议浮层。Windows 使用 `Ctrl+Shift+Space`，macOS 使用 `Cmd+Shift+Space`；开启远端优先快捷键模式时，Windows 快捷键交给远端，仍可点击工具栏入口。

- 输入至少两个非空白字符后，自动显示当前会话的本机命令历史建议，不调用模型。
- 唤起浮层后按 Enter，可让 AI 续写当前命令前缀；空命令行时可以输入中文目标，例如「找出占用 8080 端口的进程」。AI 须先在设置中启用并配置模型。
- 点击「填入」或按 `Alt+Enter` 仅补入命令后缀。用户可继续在 Shell 中编辑，再自行回车执行。Tab、方向键等仍交给远端 Shell。
- 最近终端输出默认不发送。勾选附加后显示脱敏快照；「更新输出快照」刷新该快照，请求使用预览中的同一份内容。
- Esc 关闭并取消请求。切换标签、重连或继续在终端输入后，旧的 AI 建议失效。自动建议不跨会话，也不进入命令广播。

可填入状态依赖 Shell 输出的 OSC 133 提示符标记。已有兼容集成的 Shell 会自动识别；没有集成时，浮层直接显示「启用 Shell 集成」。确认当前终端位于空白的 Bash / Zsh 提示符后，按钮会执行固定初始化脚本；收到 Shell 的提示符确认才显示启用成功，并保留已经生成的 AI 命令供填入。初始化不会执行 AI 建议；取消、断线和超时均不会把建议自动发送。失败可重试，也可展开「手动启用与兼容说明」复制脚本。

已有基础标记的会话可通过「增强执行结果识别」重新启用。脚本为本次 Shell 添加 A/B 提示符标记、C 执行起点和 D 退出状态，保留现有 PS0/PS1 与提示符钩子，不写启动文件、不替换 DEBUG trap。Bash 4.4 以下通过已验证的命令回显确定输出起点。重新连接后可能需要再次启用；持续重写 PS1 的主题可能覆盖标记。0.1.23 的安装和交互验收见 [本地验收记录](../../docs/local-build-validation-0.1.23-2026-10-22.md)。

未识别到提示符时仍可生成、复制命令，但不直接填入。执行中、密码输入、备用屏幕，以及未能核实远端回显时暂停填入。用 Tab 或方向键等操作改变命令行后，本轮建议暂停；新提示符或经回显确认的 `Ctrl+U` 清空可恢复。建议入口仅生成单行命令，不自动执行。

## 命令结果与 AI 续诊

终端工具栏和 AI 面板提供「执行记录」。已跟踪的单行输入、快捷命令和经过确认的 AI 草稿共用记录，展示命令、时间、原连接、执行状态及可取得的真实退出码。

- OSC 133 C/D 界定执行输出。只有提示符结束边界时，记录明确显示退出码未知；仅发送成功、输出 ACK 或一段时间没有输出，都不能代表执行完成。
- 点击「分析这次结果」将该命令及其脱敏输出放入 AI 请求预览；点击「下一步命令」在终端建议浮层中附加同一份结果快照。两者均由用户继续提交模型请求，后续终端输出不改变已选快照。
- 多行命令、未知输入位置、滚动缓冲区丢失及全屏程序无法提供可靠输出范围时，不猜测结果。重连后的旧记录仍可回看，不能用于向新连接继续发起执行。
- 每标签最多保留 40 条记录、合计 256 KiB 输出；每次输出最多 16 KiB。记录仅在内存保留，常见凭据先脱敏，截断时舍弃不完整的软换行内容。PTY 的后台消息可能混入执行期间的输出，AI 上下文中会说明这一限制。

## 上传下载与失败恢复

选择文件、目录或拖入文件后，会先显示共用的传输确认单，列出来源、目标主机、保存路径和同名处理策略。文件选择时捕获目标连接和路径，后续浏览其他目录不会改变该批任务，上传完成也不会把浏览目录拉回原位置。上传支持普通文件和递归目录，跳过符号链接与特殊文件；目录上传与下载均支持合并及空目录。

上传和下载使用相同的冲突界面，比较两端路径、类型、大小和修改时间，可覆盖普通文件、跳过、重命名或保留两份。新名称必须尚未占用，新建和重命名目标均使用后端禁止覆盖写入。批量决定只作用于本批；取消冲突会丢弃整批尚未提交的任务。检查目标和扫描目录期间也可以取消。

全局传输管理器可以重试单项或勾选重试失败／已取消任务。后端沿用原任务的连接、两端路径及覆盖决定，新增任务并保留原错误记录和重试来源。原 SFTP 面板关闭后，失败／已取消任务仍在现有保留期内维持原连接：默认最多保留 200 条已结束任务、30 分钟，定期清理后释放连接；应用退出不保留这些任务。原连接已经失效时显示错误，需在原主机重新选择文件，不会借用当前活动主机。

全局队列支持按主机、方向、状态和实际传输批次筛选。批次由后端保留，重试继承原批次。卡片的「远端目录」会核对原保存会话及地址，再定位到该主机的来源／目标目录；原会话已删除或改为其他地址时提示手动定位。

## 上下文来源与分步诊断

「终端选区」「最近输出」「执行结果」和手动粘贴的「文件片段」会作为独立快照进入来源清单。每项可取消附加或移除，并显示主机、Shell 最近报告的目录、采集时间、字节数以及脱敏／截短状态。最多 6 项，每项最多 8 KiB；发送前预览共用 16 KiB 上下文上限，明确提示截短或省略。连接变化后，旧来源需移除或取消附加，不能直接作为新连接的当前状态发送。

诊断回复若包含有效的 `xsh-plan` 结构，显示「审阅诊断计划」入口。每步列出检查目标、假设、命令及预期观察，可编辑单行命令、跳过或暂停后续步骤。每次仅执行当前已审阅的一步，另行确认原主机与连接；实际记录通过唯一执行 ID 关联，不按命令文本或“最近输出”猜测。返回结果可附加到下一次问题，由用户预览并发送，不自动请求模型或连续执行。格式不完整或不符合结构要求的回复仍可作为普通文本阅读。

计划和上下文仅保存在本窗口对应标签的内存中。任务摘要、显式保存的主机／项目记忆尚未实现；假设与预期的修改目前通过重新生成方案完成。

## 目录工作区

远程文件面板增加按主机、端口和用户区分的目录书签与最近访问，清楚展示并允许选择本地保存目录。下载默认进入该目录的批次确认；用户仍可在确认单编辑具体目标。

点击双栏按钮可展开本地和远端列表。本地目录采用原生浅层读取，上限 5000 项；双击目录进入，可混合选择文件和目录后送入已有上传确认和冲突流程。递归上传会在全部冲突决定完成后开始创建目录及传输文件，保留空目录。

Shell 集成通过 OSC 7 报告目录，不从日志或任意输出猜测路径。「跟随终端」只使用当前连接报告的目录；重连后等待新的报告。目录终端按钮在当前终端发送经过确认、正确引用路径的 Bash/Zsh `cd` 命令。目录偏好存于本机 WebView 存储，不作为 AI 持久记忆。

## 约定

- 使用 pnpm，不提交 `package-lock.json` 或 `npm-shrinkwrap.json`。
- 终端和凭据相关改动必须同时检查 macOS 与 Windows 行为，避免抢占远端 Shell 的 Ctrl 控制键。
- 不在前端 localStorage、导出 JSON、日志或命令片段中保存密码、Key Passphrase、Token 或私钥内容。

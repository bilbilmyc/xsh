# v0.2.6 Windows 更新安装栈溢出

## 问题与修复

旧版可以检查更新、下载并校验安装包，但调用安装接口时，XSH 主进程在启动安装器前发生栈溢出。单独运行同一个安装包可以成功，所以仅验证安装器参数和同版本覆盖无法覆盖这条故障路径。

本机通过已安装程序的实际前端更新模块及 Tauri IPC 复现，使用官方 GitHub Release 和真实下载文件。运行时跟踪捕获到 `desktop.exe` 内的 `stack-overflow`，没有捕获到安装器的 `CreateProcessW` 调用。用户截图中的 `Error launching CrashSender.exe` 是随后出现的崩溃报告错误；该进程加载的 `CrashRpt1500.dll` 来自微信输入法。未修改输入法或替换其组件。

`verify_installer` 将 64 KiB 数组保存在异步状态中；回归测试测得该 Future 为 65,840 字节。IPC 包装层构造、移动 Future 时会进一步消耗 Windows UI 线程栈。修复将读取缓冲改为堆上的 `Vec`，保留安装前的文件大小和 SHA-256 校验。

新增回归要求校验 Future 小于 8 KiB：旧代码失败，修复后通过。这样后续重新引入大的内联数组时会直接失败，而不依赖单元测试线程更大的默认栈去发现问题。

修复提交：`b366a55`。v0.2.5 已正式发布，因此本次修复使用新的 v0.2.6 标签；没有替换旧标签或重传同版本修复包。

- 更新模块：10 项测试通过，包含 Future 栈预算、安装前篡改校验和下载完整性；1 项联网测试默认跳过，真实下载由安装程序集成验证覆盖。
- 前端：159 项测试和生产构建通过。
- Rust：v0.2.6 的 `cargo test --workspace --release` 全量 207 项通过、1 项联网测试默认跳过，文档测试通过；`cargo fmt --all -- --check`、`cargo clippy --workspace --release --all-targets -- -D warnings` 通过。
- 本机修复基线：将修复编入临时 v0.2.5 测试包，调用尚未下载时的安装接口能正常返回校验错误，进程保持运行；5 项本地偏好的摘要保持一致。这份测试基线与公开 v0.2.5 安装包不同。

鼠标定位和窗口捕获存在工具限制；运行时集成验证通过真实更新函数与 IPC 完成，界面版本及会话数量通过原生可访问性状态核对。没有使用模拟发布接口或模拟下载安装包。

# XSH 0.1.23 Shell 集成入口与覆盖安装验收

日期：2026-10-22，Asia/Shanghai。平台：Windows x64。基于 0.1.22 的本地工作区继续修改，未提交。

## 问题与修复

未集成的终端能生成 AI 命令，但「填入」不可用。原来的入口藏在折叠说明内，按钮仅粘贴脚本，还需要用户自行回车。

0.1.23 在命令建议浮层直接显示「启用 Shell 集成」。确认当前终端停在空白的 Bash / Zsh 提示符后，在原连接执行固定初始化脚本。仅收到 Shell 返回的首个空白提示符并核实回显后才显示成功、启用填入，原 AI 建议保留，无需再次请求模型。

- 初始化仅对当前 Shell 生效，不修改远端启动文件。
- 初始化不执行 AI 建议。后续「填入」仍只填写命令，由用户自行回车。
- 确认框标明目标会话；确认期间发生断线、切换终端、输入变化或进入全屏程序，会拒绝发送到变化后的目标。
- 初始化写入失败或 10 秒内没有收到提示符确认，会显示重试及手动启用入口；不会仅凭写入成功就宣称集成成功。
- 原建议仅能恢复到原连接的第一个空白提示符；后续命令或其他连接不能继承该建议。

安装版使用真实 Tauri IPC、Rust AI 流式请求和环回 SSH 服务。AI 服务提供确定性 `pwd` 建议，Shell 是实际 Git Bash。SSH 服务记录收到的输入，核对取消时没有输入，确认时只接收初始化脚本及回车，点击填入时只接收 `pwd` 而没有回车。收到实际 Bash OSC 提示符标记后，界面保留原建议并启用填入。

## 验证边界

- 真实 Shell 验证使用 Git Bash；Zsh 和 macOS 本机行为未在本轮实机验证，原初始化脚本未改动。

- AI 使用确定性测试服务，本轮不评价线上模型回答质量。
